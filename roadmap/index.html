Roadmap

What ships, what runs, and what is planned.

Nodeau has a working Self-Hosted Alpha, and a multi-node control plane that runs on real hardware but is not in the installer yet. Those are different things, and this page never lets them blur.

Available

Ships in the public Self-Hosted Alpha. Install it and you have it.

In Alpha

Built and physically validated on real hardware, but not yet the supported public install path.

Next

Being worked on now, or the immediate priority once the current work lands.

Planned

Intended and designed for, but not built. No code you can run.

Exploring

A direction we think is right and have not committed to. Intent, not plan.

There are no dates on this page. Nodeau is a small effort and a date would be a guess presented as a commitment.

Now — the public Alpha

Available

Everything here is in the published Self-Hosted Alpha (), running on a single Linux machine with a single NVIDIA GPU. This is what you get by following the install guide.

Self-hosted installer

Available

One public command. Verifies the release artifact before installing anything.

nodeau install

Available

Checks the machine, shows a plan and every privileged command, then sets up the local infrastructure — adopting what is already there rather than replacing it.

nodeau doctor

Available

Read-only diagnosis of the host, GPU, driver, container stack and storage.

nodeau quickstart

Available

Model consent, download, verification, admission, deployment and a local endpoint in one command.

VRAM-aware admission

Available

Decides whether a workload fits before scheduling it, and explains the arithmetic either way.

Reservation accounting

Available

Tracks what Nodeau has already committed on a GPU, so a second workload is judged against reality.

GPU hardware observation

Available

A node agent reports the GPU's real addressable memory and current usage.

Model profiles that carry their source

Available

Where a configuration has been measured on real hardware, Nodeau uses the measurement. Where it has not, it derives a conservative estimate from the model’s own architecture, adds a further margin, and labels the decision as estimated. An estimate is never shown as a measurement.

Model artifact verification

Available

Downloaded from the publisher, checked against a known SHA-256, quarantined on mismatch.

Local OpenAI-compatible API

Available

Bound to 127.0.0.1 with a locally generated key. Streaming supported.

Support bundles

Available

One redacted archive for diagnosis. Nothing is uploaded.

Install ownership ledger

Available

Records what Nodeau installed as distinct from what it found, and prints an uninstall plan before making any change. It does not remove things that were on the machine before it.

Reproducible release artifacts

Available

Pinned versions and checksums, verified end to end before publication.

In Alpha — built and running, not packaged

In Alpha

These run in the current development build and have been validated on two physical machines carrying different NVIDIA GPUs. They are not in the public installer: adding a second machine is still a manual step rather than a supported Nodeau command.

Multi-node GPU discovery

In Alpha

More than one GPU machine under a single control plane, each publishing its own hardware state and being reasoned about separately.

Per-machine hardware observation

In Alpha

Addressable memory, current usage and attached-display state, reported by each machine about itself. On the two-machine cluster every value differed between them, as it should.

Per-machine model verification

In Alpha

Each machine computes a SHA-256 over its own copy of the model and publishes the digest. A machine whose copy is missing, unverified or wrong is not a placement candidate at all. This found genuine silent corruption on a second machine that had been serving answers and reporting healthy.

Explainable placement across candidates

In Alpha

The fit calculation runs once per candidate machine, and every candidate keeps a reason — including the ones that lost. There is deliberately no second, looser rule for choosing a machine.

Heterogeneous GPU reasoning

In Alpha

An RTX 3080 and an RTX 2080 in the same cluster, each scored on what it can actually give the workload rather than treated as one interchangeable “GPU”.

Placement stickiness

In Alpha

A healthy workload is not restarted elsewhere because another machine scored better. Observed doing exactly that on real hardware, with the other machine genuinely winning on score.

Node-scoped isolation

In Alpha

Each machine’s agent can write only its own state, and can read no credentials at all. Verified in both directions on two machines.

What this does not yet show. A workload has been decided across both machines, but has not been started on the second GPU. No machine has been switched off to see what happens, and there is no automatic failover — that work is further down this page, unbuilt.

Next — package and expand

Next

The immediate priority is turning the multi-node foundation into something a person can install, and widening the hardware it has met.

A supported multi-node command

Next

Adding a second machine currently means driving the underlying cluster by hand. Turning that into a safe, checked Nodeau command — and shipping it in the installer — is the packaging job that stands between “In Alpha” and “Available” above.

Broader hardware validation

Next

Nodeau has now been installed and run on two machines with two different NVIDIA GPUs. That is two data points, not a compatibility list, and widening it is the current gate.

Installer edge cases

Next

More failure modes handled cleanly, better recovery, clearer diagnostics.

More measured NVIDIA GPUs

Next

Additional cards measured rather than estimated. Nodeau runs on an unmeasured card today by estimating conservatively and saying so, but a measurement is still the better answer and is what should end up in the catalogue.

More Ubuntu and Linux coverage

Next

Beyond the single measured Ubuntu 24.04 baseline.

Upgrade and repair flow

Next

Moving between versions without reinstalling from scratch.

More model profiles

Next

More models and quantisations, with measured memory and throughput.

Windows via WSL

Planned

The GPU path through WSL is genuinely different and is currently refused rather than half-supported. Native Windows is not planned.

Home experience

Planned

Easier model browsing, simpler configuration, better local status. A graphical interface is possible later but is not committed.

Planned — smarter placement

Planned

Placement decides on fit today: can this machine safely hold this workload, and which safe machine leaves the least waste. These would make it decide on more than fit. None of them is built.

Model locality as a preference

Planned

Nodeau already knows and verifies which machines hold a good copy of a model, and refuses to place a workload on one that does not — that part is In Alpha above. Preferring a machine that already holds it, so a cold start does not pay for a download, is a scoring change that has not been made.

Performance-aware placement

Planned

Choose using measured throughput rather than fit alone. A card that fits is not necessarily the card you want.

Multi-machine capacity planning

Planned

Answering “what could this cluster hold?” rather than only “where does this one workload go?”.

Planned — fleet operations

Planned

Once workloads move between machines on purpose, the organisational layer becomes the useful part. None of this exists — in the Alpha or on a branch.

Fleet inventory and health

Planned

What hardware exists, what is running on it, and what is wrong.

Model inventory and rollout

Planned

Which models are where, and moving between versions deliberately.

Team access and organisation RBAC

Planned

Who can deploy what, where.

Quotas and policy

Planned

Limits and placement rules expressed once, enforced centrally.

Audit history

Planned

A durable record of decisions and changes.

Observability and alerts

Planned

Utilisation, saturation and failure surfaced rather than inferred.

Health-aware rescheduling and failover

Planned

Recovering a workload elsewhere when a machine fails. Nodeau does not do this. Placement deliberately keeps a healthy workload where it is; noticing that one has stopped being healthy, and acting on it, is a separate capability that has not been built or tested.

Maintenance and drain workflows

Planned

Taking a machine out of service without dropping what it was running.

Exploring

Exploring

Directions we think are right but have not committed to. Treat these as intent, not plan.

Cloud overflow

Exploring

Owned hardware first, cloud when policy or capacity requires it. Hybrid scheduling across both.

Nodeau-hosted control plane

Exploring

A managed management plane over infrastructure you still own. Inference would not inherently need to traverse it simply because management is hosted.

Multiple GPUs inside one machine

Exploring

A genuinely different problem from multiple machines, and not solved by it. Nodeau works with one GPU per machine today, however many machines there are.

AMD GPU support

Exploring

A different runtime and memory story, not a configuration flag.

macOS support

Exploring

Unified memory changes the admission model substantially.

Broader runtimes

Exploring

vLLM and others alongside llama.cpp.

Automatic quantisation

Exploring

Fitting a model to a card rather than refusing it.

Scale to zero

Exploring

Release the GPU when idle, reload on demand.

Git-to-deploy

Exploring

A repository as the unit of deployment.

Air-gapped and private registries

Exploring

For organisations that cannot pull from the public internet.
