FAQ

Questions, answered plainly.

Including the ones with awkward answers. Where something is roadmap rather than reality, it says so.

About Nodeau

What is Nodeau?

Software that turns a computer with a compatible NVIDIA GPU into local AI infrastructure. It checks the machine, works out whether a supported model can fit safely in the GPU’s memory, sets up what is needed to run it, and gives you an OpenAI-compatible API on that machine.

Who is Nodeau for?

Two groups. Home: an individual with a gaming PC or workstation who wants to run models locally without becoming an infrastructure engineer. Business: teams and organisations with GPU hardware they want to operate as shared infrastructure.

The Business side is no longer only an intention. The control plane runs across more than one GPU machine and has been validated on two with different NVIDIA generations. What it is not yet is packaged — see “What does In Alpha mean?” below.

What does “In Alpha” mean on this site?

Three states, kept apart deliberately.

Available — it ships in the public Self-Hosted Alpha. You install it and you have it.

In Alpha — it is built and it has been validated on real hardware, but it is not in the public installer yet. Multi-node and mixed-GPU reasoning are here.

Planned or Exploring — not built. There is no code you can run.

The distinction exists because collapsing it would force a capability that genuinely works to be described as either unbuilt or fully shipped, and both would be wrong. The roadmap labels every item.

Do I need to know Kubernetes?

No. Nodeau uses Kubernetes underneath, but normal use is three commands and an API. You never write YAML, and you do not need to know what a container is. Running across several machines is the one place that leaks today — which is exactly why it is not presented as a supported workflow yet.

Is Nodeau open source?

Not at this time. The installer and the published distribution are public; the platform source is not.

Getting started

How do I install it?

Three commands, on a machine that already has a working NVIDIA driver:

curl -fsSL https://get.nodeau.ai/install.sh | bash
nodeau install
nodeau quickstart

The Alpha guide walks through each one.

How long does it take?

Roughly ten minutes of setup, plus the model download. The starter model is about 4.7 GB, so on a slow connection that is the long part.

Does it cost anything?

The Self-Hosted Alpha is free and needs no account or card. See pricing for where this is heading.

Can I uninstall it?

Yes. nodeau uninstall shows an uninstall plan and asks before changing anything. Nodeau records what it installed as distinct from what it found, so it does not remove things that were on the machine before it — your downloaded models, your GPU driver, and a Kubernetes cluster it did not create all stay.

If you had your own Kubernetes cluster and Nodeau adopted it, uninstall is less thorough than the plan suggests and can leave Nodeau’s own components behind. That is a known gap we are fixing; nothing of yours is at risk from it, and nodeau support bundle plus an email will get you a hand.

Hardware

What GPUs are supported?

NVIDIA only, one GPU per machine. Three categories, and it is worth keeping them apart:

Physically validated — Nodeau has been installed and run end to end on an RTX 3080 and an RTX 2080, both under Ubuntu 24.04.

Fully measured — only the RTX 3080. Its memory behaviour for the starter model has been measured directly, so admission on that card uses a real figure.

Everything else — untested rather than known-broken. Nodeau will still run: it derives a conservative memory estimate from the model’s own architecture, carries an extra safety margin, and tells you plainly that the number is estimated. It does not pretend an estimate is a measurement, and it does not pretend every NVIDIA card is known to work.

Does Nodeau install my NVIDIA driver?

No, deliberately. A working driver is a prerequisite. Installing or changing a GPU driver affects whether your machine boots to a desktop, and Nodeau will not make that decision for you. It checks the driver, and stops with an explanation if it is not working.

What happens if nvidia-smi doesn’t work?

Nodeau stops before changing anything and tells you the driver is not working. Fix the driver first — through your distribution — then run nodeau install again.

Does Nodeau support Windows?

Not today. Native Windows is not planned. Support through WSL is on the roadmap and is currently Planned, not available — the GPU path through WSL is genuinely different and untested, so the installer refuses cleanly rather than half-working.

Does Nodeau support WSL?

Not yet. It is detected and refused rather than attempted. It is on the roadmap.

Does Nodeau support AMD GPUs?

No. It is listed under Exploring on the roadmap — a different runtime and memory model, not a configuration flag.

Does Nodeau support macOS?

No. Also Exploring. Unified memory changes the fit calculation substantially.

Can Nodeau use several GPUs?

These are two different questions, and Nodeau’s answers to them differ.

Several GPU machines, one control plane — yes, and it has been validated on two machines with different NVIDIA generations. It is In Alpha: real, but not yet in the public installer, which sets up one machine.

Several GPUs inside one machine — no. Nodeau works with one GPU per machine, however many machines there are. This is genuinely a different problem from multi-node and is not solved by it; it is marked Exploring on the roadmap.

Models

What models can I run?

In the Alpha, a small set with measured profiles. The starter model is Qwen3-8B Q4_K_M (Apache-2.0, about 4.7 GB). Run nodeau model list to see what your installation can serve. More models are a near-term priority.

Why so few models?

Because a good answer costs work. A model profile starts as measurements on real hardware, not a formula, and adding a model properly means measuring it. Nodeau can fall back to a conservative estimate derived from a model’s architecture — that is what lets it run on cards nobody here owns — but an estimate is the fallback, not the goal, and Nodeau always says which one it used.

How does Nodeau know if a model will fit?

It compares what the GPU can actually give a workload — the memory the compute API can address, minus what is already in use outside Nodeau, minus what Nodeau has reserved for other workloads, minus a safety reserve — against what that model needs in that configuration, plus a margin. If the result is negative it refuses and shows the arithmetic.

The “what the model needs” number is either measured on hardware like yours, or estimated from the model’s own architecture with an extra margin added. The decision tells you which. That matters: an estimate carries more uncertainty, and you should know when you are relying on one.

Why isn’t all my advertised VRAM available?

Three reasons. Some of the card’s memory is not addressable by the compute API at all. Your desktop is already using some of it. And a workload that fits with nothing spare will fail as soon as anything else allocates. Nodeau plans against what is actually usable rather than the number on the box.

Where do models come from?

From their original publisher, over HTTPS, at a pinned revision. Nodeau does not redistribute weights. Every download is checked against a known SHA-256 before it is used, and a file that fails is quarantined rather than left where a later run might trust it.

Privacy and networking

Does Nodeau run my model in the cloud?

No. The model runs on your GPU, on your machine. There is no Nodeau-hosted GPU involved.

Does Nodeau send my prompts anywhere?

Nodeau does not collect or transmit prompts or model output, and there is no telemetry in the Alpha. Your requests go to a model running on your own hardware over the loopback interface.

One honest caveat: if you point a third-party application at the endpoint, that application can do whatever it likes with your data. Nodeau cannot make promises about software it did not write.

Is Nodeau exposed to my local network?

No. The local endpoint binds 127.0.0.1 and nothing else — not 0.0.0.0, not a LAN address — and there is no setting to change that in the Alpha. You can check with ss -tlnp | grep nodeau.

Is the API authenticated?

Yes. A key is generated locally with a cryptographic random source and stored with owner-only permissions. Requests without it, or with the wrong one, are rejected. Reveal it with nodeau auth show.

Is the API OpenAI-compatible?

Yes, including streaming. Most OpenAI clients work by pointing base_url at http://127.0.0.1:8080/v1.

Does Nodeau need internet after setup?

Not for inference. It needs the network to install, to download container images, and to fetch a model the first time. After that the model is cached locally and inference is entirely local.

The Alpha

Is Nodeau production-ready?

No, and please do not treat it as such. It is an experimental Alpha with no uptime guarantee, no failover and no support commitment, and it is not hardened for hostile multi-tenancy.

Has this been tested on more than one machine?

Yes — on two. Nodeau was installed from the published release onto a second, separate machine with a different NVIDIA GPU (an RTX 2080 against the development machine’s RTX 3080), and it served a model there. The two now run as one cluster, each observing its own hardware and verifying its own copy of the model independently.

Two machines is not a fleet, and both belong to the same person. Broad validation across hardware nobody here owns has still not happened, and that is what testers and design partners are for.

Does Nodeau fail over to another machine?

No. This is worth stating flatly because multi-node capability invites the assumption. Nodeau decides where a workload should run and deliberately keeps a healthy workload where it is; noticing that a machine has died and recovering the workload elsewhere is a separate capability that has not been built or tested. Treat every endpoint as something that stops when its machine stops.

What happens if the installation fails?

It should fail safely: Nodeau stops, tells you which stage it stopped at and why, lists what it had already changed, and states what it did not touch — your driver, Secure Boot, your bootloader, your partitions and your personal files. Re-running nodeau install is safe.

How do I send a diagnostic report?

Run nodeau support bundle. It writes one .tar.gz with no API keys, no credentials, no prompts and no model output, and it uploads nothing — you attach it yourself. If the CLI will not run at all, send ~/.local/state/nodeau/install.log instead. Email either to founders@nodeau.ai.

Should I try to fix a broken install myself?

Please don’t. If you have to repair Kubernetes or container plumbing by hand, that is a bug we need to see. Send the bundle and let us fix Nodeau instead.

Business

Can Nodeau manage multiple GPU machines?

Yes, and it has been validated on two. Each machine publishes its own hardware state and independently verifies its own copy of the model; the control plane evaluates every machine as a candidate for a workload, applies the same fit arithmetic to each, and keeps a reason for the ones it did not choose.

The honest caveat is packaging. This is In Alpha: the public installer sets up a single machine, and adding a second currently means driving the underlying cluster by hand. A supported command for it is the next piece of work.

Can Nodeau manage different GPU models together?

Yes — that was the point of validating on two unlike cards rather than two identical ones. An RTX 3080 and an RTX 2080 in the same cluster are reported and scored separately, on what each can actually give a workload. Nothing anywhere in Nodeau treats “a GPU” as a unit of capacity.

Also In Alpha. And one limit worth being exact about: Nodeau has decided across both cards, but a workload has not yet been started on the second one.

Can teams share GPU infrastructure?

Partly. The machine-level foundation is there — several machines, one control plane, one place that decides. What is missing is the organisational layer: team accounts, per-team access control, quotas and policy are all Planned and unbuilt. Nodeau does not know who you are beyond an API key today.

Will Nodeau support quotas and policies?

Quotas, placement policy and organisation RBAC are Planned Business capabilities. None are in the Alpha.

Will Nodeau support audit and enterprise access controls?

Audit history and organisation-level access control are Planned. No dates.

Will Nodeau support cloud overflow?

Policy-controlled overflow to cloud capacity — owned hardware first, cloud when policy or capacity requires it — is Exploring. It does not ship today.

How do I get involved early?

If your team has GPU hardware sitting under desks or in a rack, we would like to hear about it. Become a design partner.
