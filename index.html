Nodeau Home

Put the GPU you already have to work.

If your PC has a compatible NVIDIA GPU, Nodeau handles the infrastructure that turns it into a usable local AI endpoint.

Owning a GPU is not the same as having AI infrastructure. Drivers, runtimes, model formats, quantisation, memory limits, containers, model servers, authentication. None of that is why you wanted to run a model in the first place. Nodeau does that part so you do not have to.

Install Alpha Read the FAQ

It checks the machine first

Operating system, GPU, driver, disk. If something is missing it says what, and stops before changing anything.

It works out whether the model fits

Nodeau compares what your GPU can really give a workload against what the model needs. If it will not fit, you get the numbers and an explanation, not a crash five seconds into loading.

It downloads and verifies the model

Fetched straight from the publisher over HTTPS and checked against a known SHA-256 before anything runs it. Cached locally, so you only download it once.

It gives you an ordinary API

OpenAI-compatible, on 127.0.0.1, with a key generated on your machine. Your existing SDKs work by changing one line.

And it keeps track of what it changed

Nodeau remembers what it installed and what was already there, and shows you the plan before it undoes anything. Your driver, your models and everything that predates Nodeau are left alone.

Nodeau Business

Different machines, different cards, one set of decisions.

Your organisation already owns GPU compute. The hard part is turning unlike machines into infrastructure that can decide, safely, where a workload should run.

Organisations end up with GPUs faster than they end up with ways to use them. A few developer workstations, a lab server, an edge box, three generations of hardware. Owning all of it tells you nothing about what could safely run where.

Nodeau’s control plane spans more than one machine. Each one reports its own hardware and checks its own copy of the model. When you deploy something, Nodeau looks at every machine, works out where it will genuinely fit, and tells you why it picked that one.

That part runs today, on mixed NVIDIA hardware. What it is not yet is a single command you can run — and that is exactly the piece design partners get to shape.

How it decides

A scheduler should know more than “GPU: 1”.

Most infrastructure knows only that a GPU exists. That is enough to start a workload somewhere, and nowhere near enough to know it will survive.

Nodeau looks at what the card can really offer this workload: the memory it can actually address, what your desktop and other programs are already holding, what Nodeau has promised to other workloads, a safety margin, and what the model needs. Then it either starts it or explains why it will not.

It also tells you where its number came from. If the configuration has been measured on hardware like yours, Nodeau uses that measurement. If it has not, it works out a deliberately cautious estimate from the model’s own shape, keeps extra room back, and says so on the decision. You never get an estimate dressed up as a measurement.

Add more machines and the same sums simply run once for each one. There is no looser second rule for choosing between them.

One more thing worth knowing: Nodeau stays out of the way of your requests. It decides and manages, but the traffic goes straight to the model. Restarting Nodeau does not interrupt anything.
