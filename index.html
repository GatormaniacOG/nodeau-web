Nodeau Home

Put the GPU you already have to work.

If your PC has a compatible NVIDIA card, Nodeau handles everything between that card and a usable local AI endpoint.

Owning a GPU is not the same as having AI infrastructure. Drivers, runtimes, model formats, quantisation, memory limits, containers, model servers, authentication. None of that is why you wanted to run a model in the first place. Nodeau does that part so you don't have to.

Install Nodeau Read the FAQ

It checks the machine first

Operating system, GPU, driver, disk, and whether Nodeau's own pieces are healthy. If something is missing it says what, and stops before changing anything.

It works out whether the model fits

Nodeau compares what your GPU can really give a workload against what the model needs. If it won't fit you get the numbers and an explanation, not a crash five seconds into loading.

It fetches and verifies the model

Straight from the publisher over HTTPS, pinned to an exact file, checked against a known SHA-256 before anything runs it. Cached locally, so you download it once.

It gives you an ordinary API

OpenAI-compatible, on 127.0.0.1, with a key generated on your machine. Existing SDKs work by changing base_url.

And it keeps track of what it changed

Nodeau remembers what it installed and what was already there, and shows you the plan before it undoes anything. Your driver, your models and everything that predates Nodeau are left alone.

Day to day

The commands you'd expect, and nothing you wouldn't.

Once it's running, the vocabulary is the one you already use for anything else on a machine. Start something, see what's running, read the logs, stop it, get the GPU back.

bash 
nodeau run qwen3-8b-q4km
nodeau ps
nodeau logs qwen3-8b-q4km
nodeau batch submit requests.jsonl --model qwen3-8b-q4km
nodeau dashboard
nodeau stop qwen3-8b-q4km --workload

A local dashboard

One command opens a read-only view of your models, workloads, GPU and decisions in a browser. It's served by Nodeau itself on your own machine, needs no extra install, and never holds cluster credentials.

Batch work that runs while you sleep

Hand Nodeau a file of prompts and it queues the job, waits for a GPU to be free, runs it, and writes the answers back correlated to your inputs. Cancel it and the card is released as soon as the process is really gone.

Diagnosis that names the problem

nodeau doctor checks the installation, not just the hardware, and every refusal carries a reason code and a remedy in plain words. Scripts get --json and honest exit codes: a refusal isn't a crash.

Nodeau Business

Different machines, different cards, one set of decisions.

Your organisation already owns GPU compute. The hard part is turning unlike machines into infrastructure that can decide, safely, where a workload should run.

Organisations end up with GPUs faster than they end up with ways to use them. A few developer workstations, a lab server, an edge box, three generations of hardware. Owning all of it tells you nothing about what could safely run where.

Nodeau's control plane spans more than one machine. Each one reports its own hardware and checks its own copy of the model. When you deploy something, Nodeau looks at every machine, works out where it will genuinely fit, and tells you why it picked that one.

We run it that way ourselves, on two machines with two different NVIDIA generations, and the interesting cases are the ones that go wrong: a card that's already busy, a model file that has quietly gone bad, a machine that reboots underneath a running workload.

How it decides

A scheduler should know more than “GPU: 1”.

Most infrastructure knows only that a GPU exists. That's enough to start a workload somewhere, and nowhere near enough to know it will survive.

Nodeau looks at what the card can really offer this workload: the memory it can actually address, what your desktop and other programs are already holding, what Nodeau has promised to other workloads, a safety margin, and what the model needs. Then it either starts it or explains why it won't.

It also tells you where its number came from. If the configuration has been measured on hardware like yours, Nodeau uses that measurement. If it hasn't, it works out a deliberately cautious estimate from the model's own shape, keeps extra room back, and says so on the decision. You never get an estimate dressed up as a measurement.

Add more machines and the same sums simply run once for each one. There's no looser second rule for choosing between them.

One more thing worth knowing: Nodeau stays out of the way of your requests. It decides and manages, but the traffic goes straight to the model. Restarting Nodeau doesn't interrupt anything.

Your account

Optional, and deliberately small.

Nodeau runs on your machines. An account is for the things that genuinely belong somewhere else: which installations are yours, which plan is in force, and a record you can look at from a laptop that has no GPU in it.

Sign in, run nodeau login on a machine, approve it, and it's linked. That's the whole flow. Nothing about your prompts, your documents or your results ever leaves your hardware, and Nodeau keeps working if this site is down.
