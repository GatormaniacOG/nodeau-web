Nodeau Home

Put the GPU you already have to work.

If your PC has a compatible NVIDIA GPU, Nodeau handles the infrastructure that turns it into a usable local AI endpoint.

Owning a GPU is not the same as having AI infrastructure. Drivers, runtimes, model formats, quantisation, memory limits, containers, model servers, authentication — none of that is why you wanted to run a model. Nodeau does that part.

It checks the machine first

Operating system, GPU, driver, disk. If something is missing it says what, and stops before changing anything.

It works out whether the model fits

Nodeau compares what your GPU can actually give a workload against what the model needs — and refuses, with the arithmetic, rather than letting it fail at load time.

It downloads and verifies the model

Fetched from the publisher over HTTPS and checked against a known SHA-256 before anything runs it. Cached locally, so it is fetched once.

It gives you an ordinary API

OpenAI-compatible, on 127.0.0.1, with a locally generated key. Existing SDKs work by changing the base URL.

And it keeps track of what it changed

Nodeau records what it installed as distinct from what it found, and shows you an uninstall plan before touching anything. It leaves your driver, your models and anything that was there before Nodeau alone.

Nodeau Business

Different machines, different cards, one set of decisions.

Your organisation already owns GPU compute. The hard part is turning unlike machines into infrastructure that can decide, safely, where a workload should run.

Organisations accumulate GPUs faster than they accumulate ways to run them: developer workstations, a lab server, an edge box, three generations of hardware. Owning them does not produce capacity awareness, placement, or any view of what could run where.

Nodeau’s control plane now spans more than one machine. Each machine reports its own hardware and independently proves its own copy of a model. The control plane then treats every machine as a candidate, applies the same fit arithmetic to each one, and keeps a reason for the ones it did not choose.

That runs on two machines with different NVIDIA generations today. It is not yet packaged behind a supported Nodeau command — which is exactly the part design partners can shape.

How it decides

A scheduler should know more than “GPU: 1”.

Generic infrastructure mostly knows that a GPU exists. That is enough to place a workload and not enough to know it will survive.

Nodeau reasons about what the card can actually give this workload: the memory CUDA can address, what is already in use outside Nodeau, what Nodeau has itself reserved, a safety reserve, and what the model needs. Then it admits the workload — or explains why it will not.

And it tells you where its number came from. Where a configuration has been measured on hardware like yours, Nodeau uses the measurement. Where it has not, it derives a conservative estimate from the model’s own architecture, adds a further margin, and says on the decision that it did. An estimate is never presented as a measurement.

With more than one machine, that same arithmetic simply runs once per candidate — there is no second, looser rule for picking a machine. The control plane is also deliberately not in the inference path: it decides and manages lifecycle, while requests go straight to the model runtime, so restarting it does not interrupt inference.
